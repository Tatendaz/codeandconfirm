# Demonstrations (evidence index)

Each item below names the run that produced the evidence and where to look. Runs live under
`$CODEANDCONFIRM_HOME/runs/<run-id>/`; the report is `report.md`, gate details are in `ctx.json`.
All runs were executed against the reference app: a private two-app Firebase project (iOS SwiftUI + Android
Compose) whose configuration is `examples/firebase-two-app.toml` with the real names swapped for generic ones.
Run ids, counts and outcomes are real.

Start with the [screenshot demo](demo.md) for published iOS and Android captures,
base comparisons, and source metadata from the intentionally broken candidate.

## Notes

- The iOS-only run (#6) also surfaced a **high data-integrity finding on the known-good PR**: a record save that
  stalled for ~74 s, followed by Cancel and an app restart, produced two persisted documents from one Save. The worker installed
  the base build, could not reproduce the stall there, restored the candidate, and classified the attribution as
  unproven; the gate therefore kept the finding blocking (FAIL) rather than waving it through. It was a real product bug
  (the offline outbox replayed the create under a fresh server id), fixed in demonstration 10.
- Every PASS/FAIL above was produced with `gpt-6-astra` verified from the Codex session rollout; the gate blocks
  when the rollout is missing or names a different model.
